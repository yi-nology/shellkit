# shellkit 0.2.0 演进设计：从标杆项目吸收的四类能力

日期：2026-11-08
状态：待实现
前置：docs/superpowers/specs/2026-11-08-shellkit-design.md（0.1.0 基线）

## 0. 为什么是这七项

0.1.0 解决了「库 + 脚手架 + CLI」，但它自己的**卖点没有被自己验证**：

- 说「生成后 make test 当场通过」，可测试框架**测不了失败分支**（网络、权限、超时）。
- 说「准」，但 README 里 108 个函数只靠 11 行手工表格描述，改代码必漂移。
- 说「写运维脚本」，但**清理、锁、重试、幂等**这四个运维刚需一个都没有。
- 只有一次性 tmp 清理，且「调用方已有 trap 就放弃清理」——这是缺陷不是设计。

七项全部对准这四条，**不新增任何运行时依赖**（只依赖 bash + coreutils/BSD 基础命令）。

行业标杆的取舍：

| 项目 | 拿什么 | 不拿什么 | 理由 |
|---|---|---|---|
| shdoc | 注释 → markdown 的解析模型 | 它的 @file/@see 全套 tag | 只要「函数上方注释即文档」，不引入 tag 强制 |
| shellspec | Mock/Stub 概念 | BDD DSL、覆盖率（要 kcov）、并行 | 现有极简断言库继续用 |
| bashly | 补全由命令定义推导的**思路** | YAML → 代码生成、Ruby 依赖 | 与「库 + 生成器」定位冲突，留待 0.3 评估 |
| argbash | — | m4 生成解析器 | cli_opt/cli_opts 已够用 |
| bash-commons | 模块边界与 Bash 3+ 兼容口径 | assert.sh 的运行期断言 | validate 已覆盖取值校验 |
| Google Shell Style Guide / 非官方 strict mode | 「-e 有盲区，关键步骤要显式检查」 | 全部风格条款 | 变成 run 包装器 |

## 1. 硬约束（沿用 0.1.0，新增两条）

沿用：Bash 3.2+；stdout 只给数据、日志一律 stderr；出参 printf -v；取值优先级
显式参数 > env > 配置文件 > 默认值；写文件必原子；库不改调用方 shell 选项与 cwd。

**新增 1：Bash 3.2 空数组安全。** 3.2 在 set -u 下遍历空数组会报 unbound variable
（本机 /bin/bash 3.2.57 实测）。全库遍历一律写成：

    for x in ${ARR[@]+"${ARR[@]}"}; do

**新增 2：新模块一律可被单独测。** 每个新函数必须有对应的 tests/test_<module>.sh 覆盖
成功路径 + 至少一条失败路径 + 至少一条「幂等/重复调用」路径。

## 2. 模块布局

lib/core 新增四个模块，bootstrap 加载顺序变为：

    error → i18n → log → str → validate → fs → os
          → trap → run → lock → retry
          → net → config → prompt → cli

依赖关系：trap 依赖 log；run 依赖 error+i18n+log；lock 依赖 fs+trap+log；
retry 依赖 log。四者都不依赖 net/config/prompt，因此可以排在其前。

## 3. trap —— 清理栈

### 接口

    trap_push CMD...          # 注册一个清理动作（存字符串，运行时 eval）；LIFO
    trap_pop                  # 丢弃最近注册的一个（不执行）
    trap_cleanup              # 逆序执行全部；幂等；单个失败不中断其余
    trap_install              # 安装 EXIT + INT + TERM + HUP；链式保留已有 EXIT trap；幂等
    trap_list                 # 逐行输出已注册动作（调试）

### 行为规定

1. **LIFO**：后注册先执行。符合「后建立的资源先释放」。
2. **幂等**：trap_cleanup 内用 _SK_TRAP_RUNNING 重入锁，重复调用直接返回 0。
   清理动作执行后即从栈中移除，因此 cleanup 结束栈为空。
3. **单个失败不中断**：动作返回非零时 log_warn 记录并继续下一个；trap_cleanup 自身
   恒返回 0（否则会掩盖脚本真实退出码）。
4. **退出码保真**：EXIT 处理器先捕获 $?，跑完 cleanup 后原样 exit 该值。

       _sk_trap_on_exit() {
         local __st=$?
         trap - EXIT INT TERM HUP
         trap_cleanup
         exit $__st
       }

5. **信号安全**：INT/TERM/HUP 用独立包装函数（处理器里 $? 不可靠），先摘掉全部 trap
   防递归，跑 cleanup 后 exit $((128 + 固定信号号))。

       _sk_trap_on_int()  { trap - EXIT INT TERM HUP; trap_cleanup; exit 130; }
       _sk_trap_on_term() { trap - EXIT INT TERM HUP; trap_cleanup; exit 143; }
       _sk_trap_on_hup()  { trap - EXIT INT TERM HUP; trap_cleanup; exit 129; }

6. **链式保留调用方已有 EXIT trap**：trap_install 时用 `trap -p EXIT` 取原始定义，
   剥掉 `trap -- '` 前缀与 `' EXIT` 后缀后存入 _SK_TRAP_SAVED_EXIT，在 cleanup 末尾 eval。
   这一条只对 EXIT 生效。剥壳失败（形态不认识）时记 log_debug 并跳过，绝不 eval 半截字符串。

7. **不自动安装**：注册不等于安装。调用方显式调 trap_install 才生效，避免库在 source
   时就改变调用方的信号行为。

### fs_tmp_init 改造

原实现「已有 EXIT trap 就放弃清理」。改为：

    fs_tmp_init() {
      fs_tmpdir >/dev/null || return 1
      trap_push '_sk_tmp_cleanup'
      trap_install
    }

若调用方已装过 trap_install（trap_install 幂等），不会重复安装。
这条同时修掉一个真实缺陷：以前与调用方共享 EXIT trap 时临时目录永不删除。

## 4. lock —— 单实例锁

### 接口

    lock_acquire NAME [WAIT_SEC]   # 0 成功；SK_PRECOND 超时/被占用；SK_USAGE 名字非法
    lock_release NAME              # 释放自己持有的锁；非自己持有则拒绝（返回 SK_PRECOND）
    lock_held NAME                 # 返回码；成功时 stdout 输出持有者 pid

### 行为规定

1. **原子性靠 mkdir**：macOS 无 flock，mkdir 是 POSIX 唯一可靠的跨平台原子操作。
   锁路径：${SHELLKIT_LOCK_DIR:-${TMPDIR:-/tmp}}/shellkit-<NAME>.lock
2. **名字校验**：只允许 [A-Za-z0-9_.-]，且不能是 . 或 ..；否则 SK_USAGE（防路径穿越）。
3. **持有者标识**：目录内写 pid（Bash 3.2 无 BASHPID，用 $$）。
4. **等待**：WAIT_SEC 默认 0（不等待，立即失败）。>0 时每秒轮询一次。
5. **stale 回收**：SHELLKIT_LOCK_STALE（秒，默认 0 = 不回收）。>0 时，若锁目录内
   pid 对应进程已不存在（kill -0 失败），或目录 mtime 超过 STALE，则 rm -rf 后重试获取。
   回收后必须重新 mkdir 竞争，不可信任「刚检查过」的结论。
6. **自动释放**：首次 lock_acquire 成功时，把统一的 _sk_lock_cleanup_all 推进清理栈
   （只推一次，用 _SK_LOCK_HOOKED 标记）。_sk_lock_cleanup_all 逆序释放所有仍持有的锁。
   lock_release 成功后从持有列表移除，因此 cleanup 不会重复释放。
7. **release 只释放自己**：读锁目录内 pid，与 $$ 不等则不动，返回 SK_PRECOND。

## 5. retry —— 退避重试

### 接口

    retry ATTEMPTS CMD...      # 返回最后一次的退出码；ATTEMPTS 非法则 SK_USAGE

### 环境变量

    SHELLKIT_RETRY_DELAY      首次重试前等待秒数，默认 1
    SHELLKIT_RETRY_BACKOFF    每次乘数，默认 2
    SHELLKIT_RETRY_MAX_DELAY  单次等待上限，默认 30
    SHELLKIT_RETRY_ON         可重试退出码，空格分隔；空=除 2 与 5 外全部

### 行为规定

1. **默认不重试 usage(2) 与 verify(5)**：参数错重试无意义，校验失败重试是浪费带宽。
   显式设置 SHELLKIT_RETRY_ON 后按该集合判断，2/5 也不例外。
2. **ATTEMPTS 校验**：必须是 >=1 的十进制整数，否则 SK_USAGE。
3. **日志**：每次失败 log_warn「attempt i/N failed (exit X), retrying in Ys」；最后一次
   失败 log_error 并原样返回退出码。日志全走 stderr。
4. **不吞输出**：命令的 stdout 直接透传，不捕获——保持「stdout 只给数据」。
5. **不依赖 sleep 精度**：SHELLKIT_RETRY_DELAY=0 时直接进入下一次尝试，测试即利用这点。

## 6. run —— 失败即带上文

### 接口

    run CMD...                 # 失败即 die，消息含命令原文与退出码
    run --always CMD...        # 即便 SHELLKIT_DRY_RUN=1 也真的执行

### 行为规定

1. **dry-run**：SHELLKIT_DRY_RUN=1 时向 stderr 打 "[dry-run] <cmd>"，返回 0，不执行。
2. **不带求值**：直接 "$@" 调用，不 eval，不拼字符串。
3. **失败信息**：die "$(_t 'command failed'): <cmd> (exit N)"，退出码沿用该命令的码。
4. **stdout 透传**：不捕获、不重定向，保证 run 出现在管道里时行为与直接调用一致。
5. **补 -e 盲区**：文档明确写出「if run ...; then / cmd || run ... 这两个位置即使命令
   失败也不会触发 set -e，正因如此才用 run 显式检查」。

## 7. fs 幂等三件

    fs_ensure_line FILE LINE
    fs_ensure_block FILE BEGIN END CONTENT
    fs_ensure_symlink TARGET LINK

1. 全部原子写（临时文件 + mv -f），全部幂等（已满足要求时零改动、返回 0）。
2. fs_ensure_line：整行精确匹配才算存在；不做子串匹配（子串匹配会把 "#1.2.3.4 x"
   误判为已有）。
3. fs_ensure_block：定位整行等于 BEGIN 的行，再往后找整行等于 END 的行；两者都存在
   时替换其间的全部内容；不存在时在文件末尾追加 BEGIN + CONTENT + END。BEGIN/END
   必须非空且不含换行，否则 SK_USAGE。文件不存在时视为空文件。
4. fs_ensure_symlink：link 已是正确的符号链接则不动；存在但不是符号链接或指向别处则
   替换；父目录自动创建。
5. 实现用 awk（BSD/GNU 通用语法，不用 gensub 等 GNU 扩展），不逐行 bash 循环——
   大文件下 bash 循环慢一个数量级。

## 8. 测试 stub/mock

### 接口（进 tests/test_helper.sh，不是运行时库）

    stub NAME [--exit N] [--stdout TEXT] [--stderr TEXT] [--body SCRIPT]
    unstub NAME
    stub_reset
    assert_stub_called NAME [TIMES]
    assert_stub_not_called NAME
    assert_stub_args NAME TEXT      # 子串匹配某次调用的参数行

### 行为规定

1. stub 通过在测试进程里定义同名 shell 函数实现；函数对 $(...) 子 shell 天然可见，
   因此 net_download 里调用的 curl 会被拦截。
2. 每次调用追加一行到 $TEST_TMP_ROOT/stubs/NAME.log，格式为「参数以单个空格连接」。
   断言用 grep -F，不做正则（避免特殊字符陷阱）。
3. --body 允许自定义逻辑（例如第一次失败、第二次成功），用来测重试与镜像回退。
4. stub_reset 清掉本次测试定义的全部 stub 函数与日志，由 test_helper 在文件结束时调用。
5. **验收性证明**：tests/test_net.sh 改为用 stub curl 覆盖「下载失败 → SK_NET」
   与「镜像回退成功」两条此前测不到的分支；这两条是本次改动的必测项。

## 9. 注释即文档

### 标注格式（全部可选，缺省取注释块首行）

    # @brief 一句话摘要
    # @param NAME 说明
    # @exitcode N 说明
    # @example
    #   fs_ensure_line /etc/hosts "1.2.3.4 x"
    # @see other_func
    # @internal     —— 从文档中隐藏

### 工具

    tools/shdoc.sh          # awk 内核，扫描 lib/**/*.sh，输出 markdown 到 stdout
    shellkit docs           # 写 docs/REFERENCE.md
    shellkit docs --check   # 校验，失败返回 SK_VERIFY

### --check 的两条判据

1. **注释覆盖**：lib 里每个不以 _ 开头的函数，其上方 5 行内必须存在以 # 开头的注释行。
   不满足则逐条列出并返回 SK_VERIFY。
2. **文档同步**：docs/REFERENCE.md 与「现渲染结果」逐字节一致（diff -q），不一致即
   SK_VERIFY 并提示跑 `shellkit docs`。

已测基线：70 个公开函数中 10 个缺注释（cli 4、log 6），本次补齐，覆盖率到 100%。

### 为什么不做 tag 强改

给 70 个函数逐个加 @brief/@param 是一次性的大改动，收益主要体现在「更好看」，而
「首行注释即摘要」已经能消掉漂移这个真问题。@param/@exitcode 按需补，不设门禁。

## 11. 验收标准

1. bash tests/run.sh 全绿（预期 13 → 18 个文件）。
2. macOS /bin/bash 3.2.57 与 CI 的 ubuntu-latest 双绿。
3. shellcheck -S warning -x 零告警；shfmt -d 无差异。
4. ./shellkit docs --check 返回 0；手工改一行源码后再跑必须返回 5。
5. trap 清理栈：注册 3 个动作，验证执行顺序为逆序、重复 cleanup 不重复执行、
   有既有 EXIT trap 时两者都跑。
6. lock：同名两个进程，后者 SK_PRECOND；前者退出后后者可获取；stale 回收可用。
7. retry：用 --body 'exit 1' 的 stub 验证 N 次后返回 1；exit 2 时只尝试一次。
8. net_download 的失败与镜像回退分支被 stub 覆盖并断言。
9. shellkit new /tmp/x && cd /tmp/x && make test 仍然当场通过。

## 12. 不做（明确排除）

- YAML/声明式 CLI 定义、代码生成（bashly 路线）。
- BDD DSL 与覆盖率（shellspec 路线）。
- shell 补全生成（从 cli_cmd 注册表推导）——留到 0.3，因为它需要 cli 模块暴露注册表
  的稳定接口，属于对既有模块的语义扩张，与本次「只加不改」的口径冲突。
- 结构化输出（table/json）、进度条、多模板——不在本轮。
