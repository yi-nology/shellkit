## 3. 设计

### 3.1 设备侧前置批（A5 + B2）

**问题**：`lib/posix/capabilities.tsv` 里 `os_name` / `os_arch` / `os_is_root` /
`os_sha256` 等标 `no`，理由却写「设备侧没有包管理器，也不该动系统包」——
与包管理器无关，是批量套上去的错误口径（`net_sha256` 反而在子集里，自相矛盾）。
同时 `require_*` / `os_has_cmd` 全缺，设备侧脚本只能手写 `command -v`。

**做法**：

1. 改 `tools/check_posix.sh` 的**理由表**（清单是生成物，不手改 tsv）：
   - `os_pkg_*` 等保留 `no`，理由换成真实原因（设备侧不该动系统包）；
   - `os_sha256` 的 `no` 理由改为「`net_sha256` 已在子集里提供哈希」；
   - 逐条核对其余批量套话，全部改成诚实口径。
2. 新进 POSIX 子集 5 个**同名**函数（纯 `uname` / `id -u` / `command -v` 实现，
   busybox ash 可用）：
   - `os_name`（linux | darwin | other，与主库同口径）
   - `os_arch`（x86_64 | aarch64 | other）
   - `os_is_root`
   - `os_has_cmd`（零参数退 2，与主库一致）
   - `require_cmd`（缺命令退 3、零参数退 2，与主库一致）
3. `bash tools/check_posix.sh --write` 重新生成清单。

**判据**：

- `tests/posix_parity.sh` 增补这 5 个函数的同名对拍用例
  （退出码 + stdout + stderr 逐字一致，绝对期望表防两边一起漂）；
- `make posix-check` 绿（清单与源码不漂）；
- 变异自证：把理由表改回套话 ⇒ 判据必须红；
- 同一份判据脚本在 dash 与 busybox ash 上原样跑（既有 CI 必需检查覆盖）。

### 3.2 弃用机器判据（A3）

**问题**：`docs/COMPATIBILITY.md` 承诺「弃用满一个 minor 才允许删除」，
但零门禁盯着；全库 grep 证明**没有天然弃用候选**（一个 `@deprecated` 都没有）。
ROADMAP 明令：不凭空造弃用 API 污染承诺面。

**做法**：

- 新增 `tools/check_deprecation.sh`（`make deprecation-check` 进 check）：
  扫描 `lib/core/*.sh` 的 `@deprecated` 注解 ——
  - 有注解 ⇒ 必须同时带「弃用版本」与 `docs/MIGRATING.md` 条目；
  - 从弃用版本到当前版本不满一个 minor ⇒ 不许删除（删除 = 基线里变 removed
    且无对应弃用记录 ⇒ 红）；
  - **零注解时空转通过**（空集合是合法状态），但门禁已武装。
- 判据 `tests/test_deprecation_gate.sh` 双向：
  - 夹具工程里造一个合规 `@deprecated` ⇒ 放行；
  - 造一个「删了但没满窗口 / 没 MIGRATING 条目」的 ⇒ 拦下；
  - **夹具不进 `lib/`**（只存在于测试临时目录）；
  - 变异自证：把门禁的窗口判断改坏 ⇒ 用例必须红。
  这是对「门禁空转」的补判据能力（坑 15：白名单/门禁类设施最容易静默失效）。

### 3.3 stable 扩充（A4，28 个全升）

**事实核查**（本轮实测，2026-11-22）：按三条件
（探针 probe ✓ + MIGRATING 有记录 ✓ + 探针断言 ⊆ 承诺返回码 ✓）
重算得 **28 个**候选，第三条件逐个程序化核对全部 PASS：

    archive_extract  archive_list      ask_multi       git_default_branch
    git_fast_forward git_fetch         git_is_dirty    git_reset_hard
    git_tag          git_worktree_add  log_debug       log_error
    log_info         log_ok            log_section     log_warn
    man_count_functions                man_module_page man_modules
    man_page         net_escape_json   net_verify      proc_is_running
    proc_start       proc_stop         proc_watchdog   scaffold_vars_set
    status_emit

（用户拍板：**28 个全升**，不排除 man_* 等开发期工具。）

**做法**（走既有流程）：

1. 源码注释加 `@stability stable`（28 处）；
2. `bash tools/api_baseline.sh --write-baseline` 重生成行为基线；
3. 重生成 `docs/API-FREEZE.md` 快照（`api-freeze-check` 钉着 stable 集合与
   返回码，不同步必红）；
4. `docs/COMPATIBILITY.md` / compatibility-check 的分级数量对账更新
   （50 → 78 stable、134 → 106 experimental）；
5. `make docs` 重生成文档投影。

**判据**：既有三道门禁全绿即验收 —— `api-baseline-check`、`api-freeze-check`、
`compatibility-check`；豁免名单 `tools/stability_exempt.txt` 保持为空。

## 4. 风险与取舍

- **A4 承诺成本**：78 个 stable 意味着这些函数此后每次行为变化必须走
  MIGRATING + 弃用窗口 —— 这正是目的；用户已确认接受该承诺面。
- **A3 空转风险**：无真实弃用对象时门禁是「armed not loaded」——
  用夹具双向自测补判据能力，避免静默失效。
- **POSIX 新增 5 函数**：每加一个同名函数就多一份两份实现漂移的风险面 ——
  由 `posix_parity.sh` 绝对期望表 + 变异自证兜住。
- **长跑诱惑**：覆盖批次容易越界混进语义改动 —— 靠「独立 PR + 批末白名单
  必须下降」两条硬规则防。
