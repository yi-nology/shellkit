# Working with AI

These constraints were written for machines in the first place: banned syntax, task-to-module mapping, and a
pre-delivery self-check. They are all decidable rules, not "please keep things tidy".

## Three artefacts, one source

| File | Audience |
| --- | --- |
| `AGENTS.md` (repository root) | AI writing code in this repository |
| `templates/AGENTS.md` | every project generated by `shellkit new` carries a copy |
| `skills/shellkit/SKILL.md` | installed as a skill into an AI client |

All three are assembled from `docs/ai/contract.md`, so **one edit updates all three**. Hand-maintaining three copies
guarantees drift, and drift means the AI generates code against an expired rule.

## Why it works

When an AI writes Bash, two failure modes dominate:

1. **Using syntax that only exists in 5.x** (`declare -A`, `${v^^}`, `mapfile`), which crashes on the bash macOS ships.
2. **Inventing function names** (`conf_require`, `log_success`), which blow up at run time with an error message
   nobody can decode.

The "do not write / write this / what 3.2 does" table in `AGENTS.md` addresses the first. `docs/REFERENCE.md`,
generated from source comments, addresses the second -- and because it is also the source of truth for
`check-docs`, "in the docs but not in the code" is impossible.

## A prompt you can paste

```text
Write deploy.sh using shellkit:
 - logging via log_info / log_ok / log_warn / log_error, all to stderr
 - read config with conf_init + conf_get_any; write it with conf_set (idempotent)
 - fail via die / require_cmd; pick exit codes from 0/1/2/3/4/5, never a blanket exit 1
 - download with net_download URL DEST sha256; wait for ports with net_wait_port
 - single instance via lock_acquire
 - run commands with run (stops on failure); inside an if, use run --no-die
 - banned: declare -A / local -n / ${v^^} / mapfile / [[ -v ]]
 - iterate possibly empty arrays as ${arr[@]+"${arr[@]}"}
 - before delivering, run bash -n and shellcheck -S warning -x and paste the real output
```

The last line is the important one: make it **paste output**, not claim "this should work".

## Pre-delivery self-check

```bash
bash -n the-scripts-you-changed.sh
shellcheck -S warning -x the-scripts-you-changed.sh
make test
```

Three criteria must hold together: **exit code 0**, **no FAIL lines**, **you read the output yourself**. Exit code
alone misses "the command never ran"; output alone misses silent failure.

## What not to let an AI do

- Do not let it "rewrite the script while it is at it". The target is the one change you asked for.
- Do not accept "this should work". Demand the actual command and the actual output.
- Do not let it invent function names: when unsure it should check the [API reference](/en/reference/index.md), and a
  name that is not there does not exist.
