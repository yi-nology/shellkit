# Thirty seconds

Generate a project, look at what it contains, add one subcommand of your own.

## Run it

```bash
git clone https://github.com/yi-nology/shellkit.git
cd shellkit
./shellkit doctor
./shellkit new /tmp/shellkit-demo --cmd start --cmd status
cd /tmp/shellkit-demo && make test
```

`doctor` reports what your environment is missing (shellcheck, shfmt, gettext, python3). **Missing tools never
block the core library** -- the library has zero runtime dependencies; the affected checks are simply skipped.

A project generated by `new` **passes `make test` immediately**. It is not an empty skeleton.

## What was generated

```text
shellkit-demo/
|-- bin/shellkit-demo      entry point: locate self → load library and app → cli_run
|-- lib/app.sh             assembly layer: config path + loads commands/*.sh
|-- commands/start.sh      one file per subcommand, a single cli_cmd line registers itself
|-- commands/status.sh
|-- config.example
|-- tests/run.sh           per-file runner
|-- tests/test_helper.sh   assertion library
|-- tests/test_smoke.sh    smoke test
|-- vendor/shellkit/       the library copy that travels with the project
|-- Makefile               test / lint / fmt
|-- AGENTS.md              constraints for AI: banned syntax, task-to-module map, self-check list
`-- .shellcheckrc
```

`vendor/` is deliberate: the project carries its own copy of the library, so CI does not need shellkit installed
and "somebody upgraded the system shellkit last week" cannot silently change what the build produces.

## Add a subcommand

Copy `commands/start.sh` under a new name, then change the function name and the trailing `cli_cmd` line:

```bash
cp commands/start.sh commands/deploy.sh
```

The new file looks like this (with the real logic elided):

```bash
cmd_deploy() {
  local __target __force=""

  cli_opt_init
  cli_opt __force --force -f
  cli_opt __target --target -t 1
  cli_opts "$@" || return $?

  if [ -z "$__target" ]; then
    __target=$(conf_get TARGET "localhost")
  fi
  log_info "deploying $__target"
  return "$SK_OK"
}

cli_cmd deploy "deploy the service" "deploy [--force] [--target HOST]"
```

**The dispatcher never changes**: `cli_run` finds `cmd_<name>` dynamically through `declare -F`, and hyphens in
the command name are translated too (`install-self` → `cmd_install_self`).

`cli_cmd` must be the last line of the file: registration happens when the file is sourced, so an early call
registers a function that does not exist yet.

## Adopt it in an existing project

You do not have to rewrite anything first. One command mirrors the library in:

```bash
cd /path/to/your-project
shellkit vendor .
shellkit vendor . --check
```

`vendor` syncs `lib/`, `locale/` and `VERSION` into `vendor/shellkit`; `--check` compares byte by byte and
returns 5 on drift, which is exactly what you want in CI to catch "somebody edited vendor locally".

One line at the top of your script wires it up:

```bash
. "$(cd "$(dirname "$0")/.." && pwd)/vendor/shellkit/lib/bootstrap.sh"
```

Only want the testing capability for now? Copy `tests/run.sh` and `tests/test_helper.sh` across. Zero dependencies.

Then work through [Five-step migration](./migrating.md). Every step can ship on its own.
