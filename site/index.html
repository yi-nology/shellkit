写运维 shell 的起点

一个约束清晰的 Bash 库、一个脚手架生成器、一套 CLI 框架。 目标不是功能多，而是让写出来的脚本又准又一致 —— 日志不会污染 $(...)， 失败有固定退出码，同一条命令跑一百遍和跑一遍一样。

$ curl -fsSL https://github.com/yi-nology/shellkit/releases/latest/download/install.sh | bash
一键安装 三十秒上手 下载 0.4.0

一条命令装上

安装脚本只做四件事：取最新版本号 → 下载 tar.gz 与 SHA256SUMS → 校验 → 交给包内自带的 shellkit install-self。它自己不往目标目录里放任何文件，安装逻辑只有一份。地址用的是 release 资产，不是 raw.githubusercontent.com —— 后者在部分网络会被重置。

# 默认装到 /usr/local；没有写权限就自动退到 ~/.local
curl -fsSL https://github.com/yi-nology/shellkit/releases/latest/download/install.sh | bash

# 指定目录 / 指定版本 / 走内网镜像
curl -fsSL .../install.sh | PREFIX="$HOME/.local" bash
curl -fsSL .../install.sh | VERSION=0.4.0 bash
curl -fsSL .../install.sh | SHELLKIT_RELEASE_BASE=https://mirror.example/shellkit bash

装完后 $PREFIX/bin/shellkit 里就这些：

shellkit update            # 更新到最新 release，sha256 对不上就不装
shellkit update --check    # stdout 只给版本号，可直接写进脚本
shellkit update --from pkg.tar.gz --sha256 SUM   # 离线或内网：指定本地包
shellkit uninstall-self    # 按 MANIFEST 删；没有清单就报错退出

校验不过就不装

sha256 不匹配直接 exit 5，一个字节都不会落地。

卸载不猜

安装时写 MANIFEST；卸载只删清单里列出的文件，../ 一律跳过。

重装不嵌套

整目录替换，不是逐文件覆盖 —— 装一百次布局都一样。

stdout 只给数据

日志一律走 stderr。所以 v=$(conf_get KEY) 拿到的永远是干净的值，不会混进 [INFO]。

出参用 printf -v

函数不直接改调用方变量。Bash 3.2 没有 nameref，这是唯一在 3.2 上可靠的返回值通道。

基线 3.2，不是 5.x

macOS 自带的 /bin/bash 就是 3.2.57。关联数组、nameref、mapfile 全库禁用。

# 生成一个工程，自带库副本、测试、Makefile 和给 AI 的约束
./shellkit new /tmp/demo --cmd start --cmd status
cd /tmp/demo && make test

# 加一个子命令 = 复制 commands/start.sh 改名 + 改 cli_cmd 那一行
# 分发器不用动：cli_run 用 declare -F 动态找 cmd_<name>

已经能跑的项目不用重写：一条命令把库镜像进去，再按五步渐进迁移，每一步都能单独上线。

shellkit vendor .            # 同步到 vendor/shellkit
shellkit vendor . --check    # 逐字节比对，漂移返回 5，适合进 CI

模块

15 个模块，一个模块一个主题。你该做的是装配，不是重新实现一遍。

模块管什么
log全部走 stderr，彩色可关
error失败即返回既定退出码（2 用法 / 3 前置 / 4 网络 / 5 校验）
configKEY=VALUE，环境变量优先，值未变不写盘
fs原子写、备份轮转、ensure_line 幂等改文件
net retry下载带 sha256 校验与镜像回退；退避重试不管用法错
lock trap原子锁与清理栈，拿到锁即挂进清理栈
cli prompt注册式命令 + --help 自动生成；超时回退默认值
str validate os run i18n3.2 兼容的字符串、校验、平台差异、失败即停、译文

给 AI 用

这个库的约束本来就是写给机器看的：禁用语法、任务落点、交付自检都写在 AGENTS.md 里。 让 AI 写 Bash 时先把它指到这几份文件，比事后返工便宜得多 —— 它不会发明不存在的函数名， 也不会写出在 macOS 自带的 bash 3.2 上直接崩的语法。

你想让它做的先喂给它
按本库写脚本AGENTS.md：Bash 3.2 禁用语法对照表 + 任务→函数落点表 + 交付前自检清单
别发明 APIdocs/REFERENCE.md：从源码注释生成，shellkit docs --check 拦漂移
在新工程里直接开工shellkit new 生成的 AGENTS.md，或装上 skills/shellkit/SKILL.md
改完自己验收让它跑 bash -n + shellcheck -S warning -x，并贴出真实输出而不是「应该能跑」

可以直接这么开口：

# 把这段当提示词的开头，比只说"用 shellkit 写个脚本"有效得多
用 shellkit 写 deploy.sh：
 - 日志用 log_info / log_ok / log_warn / log_error，全部走 stderr
 - 读配置用 conf_init + conf_get_any；改配置用 conf_set（幂等）
 - 失败用 die / require_cmd，退出码按 0/1/2/3/4/5 分，不要一律 exit 1
 - 下载校验用 net_download URL DEST sha256；等端口用 net_wait_port
 - 同时只跑一个实例用 lock_acquire
 - 禁用 declare -A / local -n / ${v^^} / mapfile / [[ -v ]]
 - 空数组遍历写成 ${arr[@]+"${arr[@]}"}
 - 交付前跑 bash -n 和 shellcheck -S warning -x
