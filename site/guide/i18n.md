# 国际化

msgid 一律英文，译文放 `locale/<lang>/LC_MESSAGES/shellkit.po`。

## 用

```bash
log_info "$(_t 'starting service')"
printf '%s\n' "$(_tn 'file' 'files' "$count")"
```

`_t` 查当前语言，查不到就原样输出 msgid —— **没有译文不会报错，只会退化成英文**。
`_tn` 处理单复数，具体形式看 `.po` 里的 `msgstr[0]` / `msgstr[1]`。

## 语言怎么定

按顺序：`SHELLKIT_LANG` → `LC_ALL` / `LC_MESSAGES` / `LANG` → 默认 `en`。
`SHELLKIT_NO_GETTEXT=1` 直接关掉查找（用于排除「是不是译文导致的」这类问题）。

## 重新生成

```bash
bash po/messages.sh
```

一条命令跑三步：`xgettext` 抽 msgid → `msgmerge` 合并进每个 `.po` → `msgfmt` 编译 `.mo`。
只检查不写盘：

```bash
bash po/messages.sh --check
```

缺 `xgettext` 的机器上 `--check` 会**跳过而不是失败** —— macOS 默认没有 gettext，
把「没装工具」当成「译文过期」会误伤一大片。

## 两个刻意的选择

### 1. 抽 msgid 时带 `--no-location`，并且用相对路径

pot 里默认会写 `#: lib/core/net.sh:42` 这样的位置注释。它有两个后果：

- 换一台机器、换一个绝对路径重新生成，整个 pot 全量 diff；
- 改一行代码让下面所有行号平移，pot 又全量 diff。

两种 diff 都不带语义，但会让「pot 是否最新」的门禁一直红。所以生成时带 `--no-location`，
并且 `cd` 到仓库根用相对路径喂 `xgettext`。

### 2. msgid 里不要带占位符

```bash
# 不要：msgid 里带具体值，永远匹配不到译文，只会留一条死键
log_info "$(_t 'deploying to $host')"

# 要：值是数据，msgid 是句子
log_info "$(_t 'deploying to'): $host"
```

带插值的 msgid 每次值不同，`xgettext` 抽出来的是当前那一次的字面量，翻译表里不可能有它。

同理，`cli_cmd` 的命令描述**不套 `_t`**：工程自己命令的描述是工程自己的事，
套上去只会给共享库的翻译表塞死键。

## 加一门语言

```bash
mkdir -p locale/de/LC_MESSAGES
cp locale/en/LC_MESSAGES/shellkit.po locale/de/LC_MESSAGES/shellkit.po
bash po/messages.sh
```

`locale/en` 的 `msgstr` 留空是有意的：英文靠 msgid 兜底，不需要维护一份和代码一样的英文表。
