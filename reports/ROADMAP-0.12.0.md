## 目标（一句话）

在**故障、异常中断、不可信输入**三种条件下，`shellkit upgrade` 要么完整成功，
要么完整保持原状，**绝不留下半截文件、越界写入、或让工程再也升不动**。

## 批次 0：确定性修复（半天，改动最小、收益最大）

> 这批的目标：把「崩溃」「静默越界」变成「明确的非 0 退出码 + 人话错误」。

### 0.1 修 `__cmds_csv` 未初始化，并把失败路径改成受控的

- **改哪里**：`shellkit` 的 `cmd_upgrade`
- **怎么改**：
  1. 读完清单立刻 `__cmds_csv="$SK_MANIFEST_COMMANDS"`（或把声明改成带默认值）
  2. 写盘失败分支改成：先清临时目录 → 再用**已推进的基线**落盘 → 再 `return "$SK_ERR"`
  3. 临时目录改用 `trap` 兜底清（注意 bash 3.2 的 trap 语义差异，见 AGENTS.md 第 1 条坑），
     不要指望每条 return 路径都记得清
- **验收**：
  - 注入 `cp` 失败 ⇒ 退出码 1，stderr **不含** `unbound variable`，含一句人能看懂的话
  - `$TMPDIR` 里不留 `shellkit-upgrade.*`（实测每次失败泄漏一个工程模板全量副本）
  - 清单里的基线与磁盘上的文件**一致**（已成功的推进了，没成功的没推进）
  - 恢复写权限后再升一次 ⇒ 被跳过的文件仍然「left alone」，模板改动仍然能升进去

### 0.2 清单里的项目名必须合法

- **改哪里**：`cmd_upgrade` 读出 `SK_MANIFEST_NAME` 之后
- **怎么改**：跑现成的 `_sk_valid_name`（`shellkit:292`）；不合法就
  `log_error` + `return "$SK_VERIFY"`（退出码 5）
- **注意**：`cmd_new` 已经在用同一个校验（`shellkit:472`），所以**不新增函数**，
  只是把 upgrade 补齐
- **验收**：`name=../../x` / `name=.` / `name=带空格` ⇒ 全部拒绝、非 0 退出码、
  **一个文件都不写**（含工程外）

### 0.3 目标路径必须落在工程目录内

- **改哪里**：同上，构造 `$__dir/$__rel` 之后、任何写操作之前
- **怎么改**：把目标路径规范化成绝对路径（`cd` + `pwd -P`，或逐段比较前缀），
  不在 `$__dir` 之内就拒绝；顺带检查 `$__dir` 本身、中间目录是不是符号链接
- **验收**：构造 `name=../../X` ⇒ 拒绝；工程内正常路径不受影响（回归全绿）

## 批次 1：写盘原子化 + 升级事务化（1~2 天）

### 1.1 写文件一律走 `fs_atomic_write`

- **为什么**：库里已经有「临时文件 + rename」，一次性解决三件事：
  ① 写盘被打断 ⇒ 目标仍是旧内容（完整），不再是 0 字节空文件
  ② 不再跟随符号链接写穿（rename 替换的是链接本身）
  ③ 模板渲染的落盘也能统一
- **怎么做**：升级路径里的 `cp -f` 换成 `fs_atomic_write`（带 mode）；
  保留 `chmod` 语义（原子写默认 644，bin 要 755）
- **验收**：
  - `cp` 替身模拟「写一半被杀」⇒ 目标文件要么是完整旧内容、要么是完整新内容，**不出现半截**
  - 悬空符号链接 ⇒ **不再**在工程外创建文件
  - `--force` + 既有符号链接 ⇒ 覆盖的是链接本身（工程内），工程外文件不动

### 1.2 升级事务化：候选 → 校验 → 切换 → 落清单 → 清理

- **目标形态**：
  1. 把新模板渲染到候选目录（现在已经是这样）
  2. **校验**：所有目标文件能写、路径合法、不越界 —— 有任何一步不满足就**在动文件之前**退出
  3. **切换**：逐个原子替换
  4. **落清单**：最后写，且写到一半也不怕（清单本身也走原子写）
  5. **清理**：候选目录、临时目录
- **明确不做**：不做自动回滚（回滚本身可能把用户的新改动一起 revert，风险大于收益）。
  事务化的价值在于「要么全成功，要么什么都没改」，而不是「失败后倒带」。
- **验收**：在 5 个阶段各注入一次失败（写失败、空间不足、校验不通过、清单写失败、被杀），
  每次结束后工程都满足：**所有文件要么全是旧版、要么全是新版**，且清单与文件一致

## 批次 2：把测试改真（1 天，这一批决定后面几批有没有意义）

### 2.1 引入测试钩子，让故障注入确定化

- **想法**：在升级流程的关键节点留一个**只在测试时生效**的钩子，例如
  `SHELLKIT_TEST_PAUSE=<阶段>`：命中就打印一行阶段标记并等待一个信号文件出现。
  阶段建议：`after-render` / `before-write` / `after-write` / `before-manifest` / `after-vendor`
- **约束**：钩子**默认关闭、不引入生产依赖**，只在 `SHELLKIT_TEST_HOOK=1` 时激活
- **验收**：测试能在任一阶段精确停住，然后注入 SIGTERM / 写失败 / 磁盘满

### 2.2 修掉两条「假绿」用例

| 用例 | 现在的问题 | 改成 |
|---|---|---|
| 「写不进去」 | 只断言退出码非 0 ⇒ 被崩溃蒙混过关 | 断言 stderr **不含** `unbound variable`、**含**预期错误文案、临时目录已清、清单与磁盘一致 |
| 「中途被杀」 | SIGINT 送不到后台进程 ⇒ 整条是空转 | 改用 **SIGTERM**（实测可达），并用 2.1 的钩子保证杀在**写盘阶段**；断言清单与文件一致 |

- **自检**：改完把修复临时回退 ⇒ 新用例必须变红（否则用例本身没判据能力）

### 2.3 runner 的失败原因要分类，超时上限要抬

- 「超时」和「断言失败」现在都印成同一句 `FAILED: <file>` ⇒ 分成两种失败行
- 每文件上限从 120s 抬到 **300s**：`test_ai_docs.sh` 本机就要 ~60 秒，贴着上限跑是定时炸弹
- **更根本的修法**：把 `test_ai_docs.sh` 里「把 6 个目录拷到隔离副本」那段做缓存/裁剪，
  让它稳定在 10 秒级
- **另有一条不稳定用例要查**：`test_http.sh` 的「没有 jq 也没有 python3 时走 grep/sed 兜底」
  在整轮 `make check` 的负载下偶发失败（兜底没把 JSON 拆行 ⇒ 贪婪匹配抓到了最后一个资产），
  单独跑 6 次全过。症状与「`tr` 没跑成」一致，但没定位到根因 —— 先把它变成确定性用例：
  断言兜底路径**拆行后**逐条匹配，而不是只断言最终 URL。
- **还有一条 TTY 用例是 flaky 的**：`test_prompt_tty.sh` 的「ask_choice 用用户输入的那个答案，
  不是默认值」在同一棵树上连跑三次会「过、红、过」；对着旧代码（HEAD）单跑是过的。
  症状是读到空串（用户输入没赶上就被默认值顶掉）⇒ pty 交互有时序假设，
  负载高时更容易复现。修法：要么等输入真的到达再断言，要么改成不依赖时序的同步点。

### 2.4 补一条**元测试**：门禁自己也要被测

- 加一条用例：故意在临时副本里制造上面 8 条缺陷中的任意一条 ⇒ 对应门禁必须报红。

## 批次 3：日志安全接口（P2，可与批次 2 并行）

### 3.1 补齐脱敏形态

- 头名：任何以 `Key` / `Token` / `Secret` / `Password` 结尾的头，
  外加 `Cookie:` / `Proxy-Authorization:` / `Set-Cookie:`
- 选项 + 值形态：`-u` / `--user` / `--password` / `--token`（短选项也要认）
- `--data 'password=xxx'` 这种「值里带敏感键名」的形态

### 3.2 显式声明机制（评审说的「安全日志接口」）

- 形态一：`run --secret-arg 2 -- cmd ...`（第 2 个参数必脱敏）
- 形态二：环境变量 `SHELLKIT_SECRET_ARGS="2,3"`
- 形态三：`run --redact-value 'my-pass'`（按**值**脱敏，适合令牌夹在参数中间的情况）
- **为什么要显式**：启发式永远漏（评估 §1.5 的表就是证据）。显式接口把「我保证它敏感」
  交给调用方，启发式只做兜底

### 3.3 反向用例

- 加用例保证**不该脱敏的别脱敏**（比如 `--verbose`、`--count`、普通 `id`）
  —— 过度脱敏会让日志失去排障价值，这也是一种回归

## 5. 门禁与提交纪律

- 每个提交：自带回归用例 + `make check` 绿 + 不破坏 0.x 向后兼容
- 公开函数上方**必须**紧邻注释行；新增公开函数要进 `docs/REFERENCE.md`（生成物，不要手改）
- 改既有函数的**结果**（退出码 / 产出文件名 / 输出文本）⇒ 升 minor 并在 `docs/MIGRATING.md`
  加「会改变结果的行为变化」表。批次 0/1 命中这条
- 建议的提交序列（每个都能单独回滚）：

      1. fix(upgrade): 失败分支不再崩溃，临时目录必清
      2. fix(upgrade): 清单项目名必须合法
      3. fix(upgrade): 目标路径必须落在工程目录内
      4. fix(upgrade): 写盘改走原子写，符号链接不再写穿
      5. feat(upgrade): 事务化的升级流程 + 明确的失败语义

      7. fix(test): runner 区分超时与断言失败；抬高每文件上限
      8. feat(log): 脱敏补齐 + 显式敏感参数声明
